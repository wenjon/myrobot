# 数字人头部交互式对话 Demo — 需求文档

- 状态: Draft
- 日期: 2026-07-27（初稿）/ 2026-09 更新
- 关联规格: `specs/2026-07-27-robot-head-design.md`
- 方法论: superpowers / brainstorming → writing-plans

## 1. 项目定位

一个会说话、有表情、能互动的**桌面 3D 数字人**。
在浏览器里渲染，用自然语言对话驱动口型、表情、头部动作；
后端 Python 编排 LLM / TTS / 记忆 / 工具。

用户价值：
- **陪伴感**：桌面上有个"活的"小人能聊天，不是冷冰冰的对话框
- **展示价值**：全链路流式语音交互的可视化 Demo
- **研究载体**：可以快速试新模型、新表情、新音色、新交互模式

## 2. 核心用户与场景

### 2.1 目标用户
- 开发者 / 爱好者：想折腾数字人交互的技术玩家
- 桌面陪伴：开着窗口当一个会动的小助手
- 展示 / Demo：AI 数字人能力的可视化展示

## 3. 功能需求

### 3.1 对话（P0）

#### 3.1.1 输入方式

- 文本输入 + 回车发送
- 语音输入（浏览器 Web Speech Recognition，可选；不支持的浏览器自动隐藏按钮）
- 新对话 / 清空历史按钮

#### 3.1.2 流式对话

- LLM 边产出边播报，不等整段结束
- 自动分句 —— 攒够一小段（12~24 字或遇强标点）就开口，不等整句说完
- 动作指令与播报文本分流 —— 模型输出里的表情/动作标记不会被念出来
- 首句延迟目标 < 2s，句间间隔 < 300ms

#### 3.1.3 轮次策略（谁该说话）

数字人正在说话时用户又发一句，需要区分意图，而不是一律硬切：

| 用户这句是 | 判定 | 行为 |
|---|---|---|
| 「停 / 别说了 / 不对 / 换个话题」 | interrupt | 立即打断，转而回应新内容 |
| 「嗯 / 对 / 好的 / 哈哈」 | backchannel | 不打断，继续把当前话说完 |
| 其它正经问题 | question | 打断，回答新问题 |

- 三种全局模式可切：`queue`（只排队）/ `always`（一律硬打断）/ `smart`（默认，先分类再决定）
- 判定必须零延迟、零成本（规则级），不能为了分类再多调一次模型

#### 3.1.4 打断体验（自然收尾）

- 点「打断」按钮 = 用户明确要求安静 → 立即硬停
- 自动 barge-in → 人性化收尾：音量渐弱留一点余音 → 嘴闭上 → 切「我在听」倾听姿态
- 被打断那轮已经说出去的话仍然记入历史（部分回答不丢）
- 目标：打断后 200ms 内停止发声

#### 3.1.5 多轮上下文

- 记得前面说过什么（默认 10 轮滑动窗口 / 4000 字符上限）
- 超限自动裁剪，被裁掉的内容异步压成摘要注入后续轮次，不是直接丢
- 上下文安全提交 —— 一轮失败/被打断时不会把半截脏数据写进历史
- 上下文体积有量化摸底，见 `docs/token-cost.md`

### 3.2 数字人模型与表现（P0）

#### 3.2.1 模型要求

| 项 | 要求 | 为什么 |
|---|---|---|
| 格式 | `.glb`（GLTF 二进制） | Three.js 直接加载，无需额外插件 |
| 口型 | **必须** 15 个 Oculus viseme（viseme_sil ~ viseme_U） | 15 个缺任何一个，那个音的口型就出不来，这是第一道硬门槛 |
| 表情 | 推荐 52 个 ARKit blendshape | 缺了就只能做有限的几种表情 |
| 骨骼 | 必须有 `Head` / `Neck` | 没有的话点头摇头只能转整个人，很假 |
| 眼球骨 | 推荐有 `LeftEye` / `RightEye` | 注视时瞳孔一起转才真实，没有也能靠 blendshape 凑 |
| 躯干骨 | 推荐有 `Spine1` | 呼吸起伏用，没有不影响核心功能 |
| 面数 | ≤ 15K 三角面 | 笔记本集显也要稳定 60fps |
| 体积 | ≤ 8 MB | 首屏加载可接受 |

#### 3.2.2 表情系统（18 种）

持续状态表情（保持到下一次切换）：

| 类别 | 表情 | 触发方式 |
|---|---|---|
| 基础 6 种 | 平静 / 开心 / 悲伤 / 生气 / 惊讶 / 疑惑 | 模型原始版本已有 |
| 新增 12 种 | 害羞 / 调皮 / 无语 / 思考 / 尴尬 / 得意 / 委屈 / 惊恐 / 厌恶 / 困倦 / 撒娇 / 期待 | 增强情绪表达 |

表情由 LLM 通过 `[表情:x]` 行内标记触发。不对称是关键设计原则：真人表情很少左右完全一样。

#### 3.2.3 动作系统（21 种）

一次性动作（触发后自动回位）：

| 类别 | 动作 | 说明 |
|---|---|---|
| 头颈 | 点头、摇头、歪头 | 分层转颈骨（Neck 60% + Head 40%），不是转整个模型 |
| 注视 | 看左 / 看右 / 看上 / 看下 / 环视 / 对视 | 眼睛先到，头随后跟上，弹道式运动 |
| 眨眼 | 眨眼 / 眨左眼 / 眨右眼 | 单眼眨就是 wink |
| 面部叠加 | 挑眉 / 单挑眉 / 皱眉 / 鼓腮 / 撅嘴 / 吐舌 / 咬唇 / 努嘴 | 在当前表情之上叠加一层，结束回落，不覆盖表情 |

动作由 LLM 通过 `[动作:x]` 行内标记触发。

#### 3.2.4 口型同步（P0）

- 15 个 Oculus viseme 全量驱动
- 逐字触发：每念一个字切一次口型
- 平滑过渡：不是瞬间切换，是插值逼近
- 口型精度：demo 级（拼音粗分，不是真音素级），能看出来在说话即可
- 说话时 jawOpen 跟随张口类 viseme

#### 3.2.5 自发微动（P1，"活着"感来源）

没有指令时也在动，这是去掉"雕像感"的关键：

- **随机扫视**（saccade）：1.2~3.8s 一次，小幅度眼球移动
- **头部微摆**：低频缓慢摆动，幅度很小
- **呼吸起伏**：`Spine1` 轻微上下，约 15 次/分
- **自然眨眼**：1.8~4.3s 随机间隔

这些不依赖任何 LLM 输出，纯本地循环驱动。

#### 3.2.6 倾听姿态（P1）

被用户打断时的自然收尾：

- 收嘴（停止当前口型）
- 歪头约 7°（侧耳倾听感）
- 眉根微抬 + 双眼微睁大（专注表情）
- 1.5 秒内如果没新内容，自动恢复

#### 3.2.7 可换脸（P2）

- 模型文件可替换，代码不改
- 有预览页可试驱表情/动作/口型后再决定
- 自动兼容性检测：加载前就知道 viseme 够不够、骨骼缺不缺
- 不兼容的模型会被标红，不会强行加载导致崩

#### 3.2.8 表现分层原则（关键约束）

表情、动作、口型、微动这四类会同时驱动同一张脸，如果各自直接写 blendshape 权重，
就会互相覆盖：说话时表情被口型冲掉、眨眼把笑脸打断。因此要求：

- 四类驱动**分层叠加**，而不是抢同一个通道：基础表情层 / 一次性动作层 / 口型层 / 微动层
- 口型优先于表情控制嘴部，表情保留眉眼；动作是**叠加**在当前表情之上的短时偏移
- 眨眼、呼吸、视线游移属于最上层微动，任何时候都不应被其它层阻塞
- 加新表情/新动作不允许破坏这个分层（改一层不影响其它层）

验收方式：说话中触发表情不掉口型；动作播完自动回到原表情，不残留。

#### 3.2.9 非功能要求

| 项 | 指标 |
|---|---|
| 渲染帧率 | 60fps（普通集显） |
| 表情切换过渡 | 平滑（无跳变） |
| 模型加载时间 | < 3s（2.7MB 当前模型） |
| 不说话时的"活着"感 | 必须有，不能像照片 |
| 多种分辨率自适应 | 支持（相机自动对准头部） |

### 3.3 语音与音色（P0）

#### 3.3.1 合成引擎（双后端 + 自动降级）

| 引擎 | 说明 | 优先级 |
|---|---|---|
| Edge 神经语音 | 微软 Azure 神经语音，自然度高，14 个中文音色可选 | 默认 |
| 浏览器 Web Speech | 离线可用，Windows 上 3 个 SAPI 音色（机械感重） | 兜底 |

降级策略：任一句合成失败只降级这一句，后续句仍走 Edge。数字人不能哑。

#### 3.3.2 音色

- 支持 14 个中文音色（Edge 神经语音）：包括女生、男生、童声、方言等
- 可选择：`XiaoxiaoNeural`（温暖女声）、`XiaoyiNeural`（活泼少女）、`YunxiaNeural`（男童声）、`YunxiNeural`（少年男声）、东北/陕西/台湾/香港/粤语音色
- 可调节参数：语速、音高、音量
- 有试听工具：`scripts/tts_preview.py` 一键生成所有候选音色样本

#### 3.3.3 韵律引擎（抑扬顿挫）

- 三种风格：`broadcast` 播音腔 / `natural` 日常口语 / `flat` 无韵律
- 语调曲线：句首起势、句中平稳、句末降调（疑问句升调、感叹句加强）
- 轻重对比：语气词拖长、强调词加重放慢、句中段落微起伏
- 停顿层级：顿号 < 逗号 < 分号/冒号 < 句号 < 省略号，层级差距刻意拉开
- 情绪联动：表情驱动声音基调（开心偏快偏高、悲伤偏慢偏低），视听一致

#### 3.3.4 口型同步

- 15 个 Oculus viseme 逐字驱动
- 时间轴来源：Edge WordBoundary 服务端返回，浏览器侧查表驱动
- 平滑过渡：插值逼近，不是瞬间切换
- 精度：demo 级（拼音粗分），能看出在说话即可；真音素级留待未来升级

#### 3.3.5 语音交互体验

- **预取合成**：入队即开始合成，与当前句播放并行，消除句间空档
- **软停打断**：被打断时音量渐弱 + 嘴闭上 + 倾听表情，不是"咔"一下断掉
- **句间节奏**：句间短暂停顿，不是机关枪一样连射
- **首句延迟**：目标 < 2s（从发送到开口说话）

#### 3.3.6 可扩展性

- TTS 引擎可替换：当前 Edge + Web Speech，未来可接 Piper / 本地音素引擎
- 音色/韵律/表情三者解耦：改一个不影响另外两个
- 调试面板：页面上可切换音色、切换韵律风格，即时对比

### 3.4 工具调用（P1）

#### 3.4.1 基本能力

- function calling —— 由 LLM 自己决定要不要调工具、调哪个、传什么参数
- 两阶段编排 —— 先非流式探测是否需要工具，再流式说最终答案（保证工具结果能进入回答）
- 多轮工具循环 —— 一轮里可以连续调多个工具（有次数上限，防死循环）
- 工具执行状态提示 —— 「正在联网搜索…」实时显示在状态栏，用户知道它没卡死
- 工具失败不致命 —— 报错作为工具结果回喂给模型，让它自己解释，而不是整轮崩掉

#### 3.4.2 已有工具

| 工具 | 用途 | 权限 |
|---|---|---|
| `get_time` | 现在几点 / 今天日期 / 星期几 | read |
| `web_search` | 实时信息、天气、新闻（Tavily） | read |
| `echo` | 联调链路用，默认不暴露给模型 | dangerous |

#### 3.4.3 加新工具的成本（可扩展性硬要求）

- 注册制：写一个 async 函数 + `@tool` 装饰器即可，不用改编排代码
- Schema 自动推导：工具名取函数名、说明取 docstring、参数取类型注解，**不需要手写 JSON Schema**
- 需要精确控制时也可以显式传 `name` / `description` / `parameters`，两种写法并存
- 目录分类即插件包：`builtin` / `web` / `document` / `database` / `hardware`，启动自动扫描注册
- CI 有 schema 静态检查（`scripts/check_tool_schemas.py`），推导错了提交不过

#### 3.4.4 权限与安全

- 每个工具声明权限等级：`read` < `write` < `dangerous`
- 全局阈门 `TOOL_MAX_PERMISSION` 默认 `read` —— 超过阈值的工具**不会**出现在给模型的工具列表里
- 单个工具有执行超时，不能拖死整轮对话
- 工具全流程有日志（调用参数 / 耗时 / 结果摘要）

#### 3.4.5 成本意识

- 工具 schema 是**每轮都要重发**的永久开销（当前 2 个工具约 148 tokens）
- 因此工具总数要控制，description 要短；`ENABLE_TOOLS=0` 时这部分开销归零
- 详细拆解见 `docs/token-cost.md`

### 3.5 记忆系统（P1）

#### 3.5.1 记忆类型（四层）

| 类型 | 说明 | 例子 | 生命周期 |
|---|---|---|---|
| 工作记忆 | 当前这轮对话正在处理的上下文 | LLM 推理中的思考过程、本轮工具返回值 | 一轮对话 |
| 情景记忆 | 具体发生过的事 | 「上周三你帮我查过北京天气」「上次你说你喜欢猫」 | 会话内保留，超限自动摘要 |
| 语义记忆 | 从事件里提炼出的稳定知识 | 「用户叫小王」「用户偏好简洁回答」「用户过敏吃海鲜」 | 永久（落盘） |
| 程序记忆 | 系统知道的做事方法 | 工具怎么用、回答风格、操作流程 | 随系统升级 |

#### 3.5.2 核心功能

- [x] **自动记住**：多轮对话后能记住用户的基本信息（名字、喜好、习惯）
- [x] **用户画像提炼**：从对话里自动抽取稳定信息，不需要用户主动告诉
- [x] **冲突确认**：新提取的画像与旧值冲突时，弹确认卡让用户拍板，不随便改
- [x] **会话摘要**：历史对话太长时自动摘要压缩，保证上下文不超限
- [x] **本地持久化**：刷新页面 / 重启后端后记忆不丢
- [x] **隐私本地存储**：所有画像、对话历史只存在本地，不上传任何服务器
- [ ] **主动记忆指令**：用户说「记住 XXX」时显式写入（P2）
- [ ] **记忆检索**：用户提到相关话题时主动回忆相关信息（P2，需向量库）

#### 3.5.3 用户画像包含哪些

- **基本信息**：姓名 / 年龄 / 性别 / 称呼偏好
- **偏好**：回答风格（详细/简洁）/ 语气（正式/随意）/ 兴趣爱好
- **习惯**：作息 / 常用地点 / 常问问题类型
- **知识**：用户告诉过的事实 / 项目背景 / 专业领域
- **关系**：重要的人 / 宠物 / 人际关系

#### 3.5.4 行为要求

- **不臆测**：不确定的信息不写入画像，或标记为低置信度
- **可追溯**：每条画像都能看到是从哪次对话里提取的
- **可编辑**：用户可以手动改 / 删画像条目
- **不打扰**：提炼过程静默进行，只有冲突时才弹窗
- **容量限制**：摘要不会无限膨胀，保持在上下文窗口安全范围内

#### 3.5.5 非功能要求

| 项 | 指标 |
|---|---|
| 记忆延迟 | 画像提炼在对话结束后异步进行，不影响回答速度 |
| 摘要延迟 | 超阈值时在轮次间隙压缩，不阻塞对话 |
| 存储大小 | 单用户长期记忆 < 100KB（JSON 文件） |
| 加载时间 | 启动时加载记忆 < 50ms |
| 冲突响应 | 冲突卡随下一条消息一起到，不额外延迟 |
| 数据安全 | 全部本地存储，不上传；可一键清空 |

#### 3.5.6 验收标准

- 先说「我叫小王」，隔几轮再问「我叫什么」，能答对
- 刷新页面后（同一会话），前面的对话记忆还在
- 说「我叫老李」（和之前冲突），会弹确认卡而不是直接覆盖
- 后端进程重启后，用户画像和历史摘要还在
- 连续聊 20 轮以上，回答仍然正常（上下文不会爆）

### 3.8 RAG 知识库（P2，设计完成待实现）

- [ ] 支持喂文档给数字人：PDF（长篇书籍 / 行业报告）、XLSX（名单类表格）
- [ ] 按文档类型分路径切块 —— 书按语义段、报告按页+图表标题、表格按行聚合
- [ ] 检索以工具形式接入（`kb_search`），LLM 自己决定要不要查知识库
- [ ] 回答要能带出处（哪本书 / 第几页 / 哪几行），不能凭空说
- [ ] 无关问题（天气、闲聊）不应触发知识库检索，避免白花 token 和延迟
- [ ] 全本地：embedding + 向量索引都在本机，文档不出网

约束与取舍：本机为集显/AMD，不依赖 CUDA；v0 只做 PDF + XLSX 两类，其它格式不做。
完整设计（选型、切块策略、目录产物、验证清单）见 `docs/rag-design.md`，规格文档第 20 章为接入摘要。

### 3.9 可观测性与调试（P1）

对话链路是流式 + 异步 + 多层叠加的，"看不见发生了什么"就没法调，所以调试能力本身是需求：

- [x] 上下文日志 —— 每轮打印**真正发给 LLM 的全部 messages**（含条数、字符数、逐条截断预览）
- [x] 记忆可见 —— 单独打印长期摘要、用户画像、待确认画像冲突数量
- [x] 输出日志 —— 打印模型原始输出（含动作标记，未清洗前）
- [x] 双通道 —— 控制台看实时、文件存全量（`backend/logs/context.log`，utf-8）
- [x] 编码健壮 —— Windows GBK 控制台遇到 emoji / 不可编码字符时降级替换，**绝不因为打日志失败而中断对话**
- [x] 一键开关 —— `LOG_CONTEXT=0` 全关，`CONTEXT_LOG_FILE=` 只留控制台
- [x] 前端状态栏 —— 连接状态、正在思考 / 正在搜索 / 正在说话，用户侧也能看到进度

详见规格文档第 21 章。

## 4. 非功能需求

### 4.1 性能

| 指标 | 目标 | 当前实现 |
|---|---|---|
| 首句延迟（发送 → 开口） | < 2s | 云端模型约 1~2s；本地 llama.cpp 视机器而定 |
| 句间间隔 | < 300ms | 预取合成把空档基本消掉 |
| 打断响应 | < 200ms | 软停 ~220ms 余音后静音 |
| 3D 渲染帧率 | 60fps | 普通集显可达 |
| 模型文件体积 | < 8MB | 当前 `avatar.glb` 约 2.7MB |
| 模型加载 | < 3s | 本地加载约 1s |
| 每轮永久上下文开销 | 越小越好 | 约 245 tokens（system + tools schema + envelope） |

### 4.2 可靠性
- TTS 失败自动降级（Edge → Web Speech），数字人不能哑
- 网络波动不崩溃，WS 自动重连
- 断网时还能本地对话（配本地 LLM 时）

### 4.3 可扩展性
- LLM 供应商可切换（ark / llamacpp / ollama），上层不改
- TTS 引擎可替换（Edge / Web Speech，预留本地 TTS 接口）
- 工具可插拔（注册制，加一个工具写一个函数）
- 表情可扩展（加一行配置 + 同步 prompt + 同步白名单）

### 4.4 安全与隐私
- API Key 不入库，走 .env
- 用户画像 / 对话历史存在本地，不上传
- 密钥扫描 CI，防止误提交
- 工具权限阈门默认 `read`，危险工具不暴露给模型
- 日志只落本地文件，不外发

## 5. 约束与假设

### 5.1 约束
- **无物理硬件**：纯软件模拟，不涉及伺服电机 / 嵌入式
- **Windows 环境**：主要在 Windows 桌面运行
- **浏览器渲染**：前端必须在浏览器里跑，不能依赖本机桌面程序
- **GPU 为集显或 AMD**：不能依赖 CUDA（Wav2Lip / SadTalker 等路线走不通）

### 5.2 假设
- 用户有稳定的网络（Edge TTS + 云端 LLM 需要联网）
- 用户熟悉基本的命令行操作（安装 Python、填 .env、启动服务）
- 本地 LLM 为可选项，不是默认配置

## 7. 验收标准（Demo 级）

详见规格文档第 8 章。核心几条：

1. 发一句话，3 秒内数字人开口说话，且口型同步
2. 打断后 200ms 内停止说话并进入倾听姿态
3. 18 种表情全部能在预览页触发，没有 blendshape 的模型会被检测并标红
4. 刷新页面后对话历史和用户画像不丢
5. 网络断开时数字人不会崩，会降级到 Web Speech 或提示错误
